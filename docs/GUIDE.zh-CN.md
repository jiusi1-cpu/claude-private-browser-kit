# 完整思路与实现逻辑

[English](GUIDE.en.md) · [检查清单](CHECKLIST.md) · [首页](../README.zh-CN.md)

## 1. 从目标而不是“防封配方”出发

实际需要的是：明确哪些程序走哪个网络出口，避免代理失效后意外直连；让 Claude 不碰日常浏览器的资料；让登录页与 MCP 网页使用同一个专用环境；任何改动都能解释、验证、回退。不能把这些目标偷换成“证明平台无法知道用户所在地”。X 社区讨论只用于提出问题，不作为风控机制的事实来源，详见 [研究记录](RESEARCH-X.md)。

| 初始要求 | 可实施的工程定义 | 不能据此推出 |
| --- | --- | --- |
| 干净 IP / 家宽 | 使用者自行选择并核验代理服务，记录实际出口、ASN 与稳定性 | ASN 或一次 IP 检测不能证明家宽、独享、声誉或账号安全 |
| IP 尽量不变 | 固定路由，重复采样，重连和重启后复测 | 本案例单次/短期相同不等于长期不变 |
| 强制 TCP、禁止 UDP | 对登记的可执行路径限制到指定 IPv4 TCP 回环端点，禁用浏览器 QUIC | 子进程、系统服务或未登记路径全部受限 |
| 浏览器禁止 WebRTC | 限制非代理 UDP，并检验 ICE 候选和真实网络行为 | WebRTC API 已被移除或所有未来版本都无泄漏 |
| DNS 必须走代理 | 新域名测试、DNS 客户端事件阳性对照，区分目标域名与上游节点解析 | `dns.enable=false` 本身就是系统级 DNS 防泄漏 |
| 语言/时区 | 专用浏览器使用已选语言；本案例明确不改系统时区 | 所有区域信号已统一或操作系统指纹被隐藏 |

## 2. 把五个不同入口拆开

1. Claude Desktop 主进程联网：使用固定本机代理配置并按程序路径限制出站。
2. Claude 自带浏览器工具：本案例最终停用，避免与专用 MCP 的入口混淆。
3. Playwright MCP 浏览器：通过独立 Node、stdio 管道启动指定 Edge。
4. 登录/帮助/外部网页：桌面端的 `shell.openExternal`，原来会交给 Windows 默认浏览器，需要独立适配。
5. Claude Code 和其他子进程：可能自己联网、执行命令或启动别的浏览器，不因前四项配置自动受控。

这解释了为什么“已配好 MCP 浏览器”之后，登录按钮仍然打开日常 Edge。两条代码路径彼此独立。

## 3. 为什么不是全局分流器

| 方案 | 优点 | 本案例取舍 |
| --- | --- | --- |
| 系统默认网页入口换成链接分流器 | 现成工具、无需改 Claude 程序 | 不采用：其他应用链接也先经过该入口，即使最后仍转交日常 Edge |
| 只开一个新的 Edge 配置文件 | 简单、Cookie 等资料分开 | 不够：不能单独约束相同可执行路径的网络，也未解决登录入口 |
| 独立程序副本 + 独立资料目录 | 可以按路径施加规则，保留日常环境 | 采用，但要维护副本的安全更新 |
| Claude 进程内外部链接补丁 | 不改系统默认关联，只改变 Claude 网页打开 | 经明确批准采用；有版本耦合和签名代价 |
| 独立 Windows 用户或 VM | 更强的账号/文件/系统隔离边界 | 不在本次实施范围，不能假装现有方案已达到同等效果 |

## 4. 浏览器与网络层

浏览器程序目录、资料目录和 MCP 工作目录分开；不从日常浏览器导入 Cookie、账号、密码、历史或扩展。不启用持久 TCP 调试端口，MCP 使用管道。独立程序副本与源文件核对签名和哈希，避免将符号链接/硬链接误认为真实隔离。

WFP 源码采用按应用路径的负向阻断过滤器：非 `127.0.0.1` 地址阻断、非指定端口阻断、非 TCP 协议阻断、IPv6 阻断。辅助程序可以使用端口 0 模式阻断全部出站。允许一个端点的意思是这些过滤器不阻断该端点，不保证其他系统规则一定允许它。

范围不自动继承给所有子进程，程序升级产生的新路径也需要登记。本例原实现的 `Verify` 检查持久标记、子层和阻断动作等基础属性，没有逐一核对地址/端口/协议条件值，因此必须配合行为测试。

本案例代理链为“应用 -> 本机专用代理 -> 可选本机中转 -> 固定上游”。开源模板只展示简单单上游结构，使用 TEST-NET 示例地址，不包含原上游、账号或口令。UDP 禁用、DNS 服务禁用和 TUN 禁用只是该代理的配置，不是对整个 Windows 的承诺。上游域名解析也需要独立审计。

浏览器参数包括固定代理、禁用 QUIC、禁用 DNS 预取、限制 WebRTC 非代理 UDP、限制普通目标域名的本机解析。它们与 WFP 配合，而非用参数代替网络阻断。保持 Chromium 沙箱；历史上专用副本因缺少沙箱读取权限无法启动，通过对程序目录补充只读/执行 ACL 解决，不开放 Profile、不用 `--no-sandbox`。

## 5. MCP 层

原案例固定 `@playwright/mcp@0.0.83`，仅安装在专用目录。公共包不分发依赖；重新部署应固定版本、保留自己的锁文件并核验依赖。

`guarded-mcp.cjs` 的运行目录约定如下，不能直接放在 `src/` 后就当成完整安装：

```text
PrivateEdge/
  Application/             用户自行准备的浏览器
  Profile/                 专用浏览器资料，绝不提交
  workspace/               MCP 截图/日志等，绝不提交
  mcp/
    node.exe               用户自行准备的独立 Node
    guarded-mcp.cjs
    browser-config.json    从模板适配，不提交
    node_modules/@playwright/mcp/
```

白名单有 19 个工具，拒绝任意宿主代码工具、浏览器安装和上传工具，但保留了浏览器 `evaluate`。这不是安全沙箱：页面脚本、表单提交、文件 URL、下载、对内网地址导航、对话框确认等仍需权限管理和目标策略，不能宣称仅白名单就阻止数据外传。专用 Node 出站阻断也不能约束有网络能力的浏览器发请求。

把配置片段合并进已有 MCP 配置，不能整体覆盖其它服务器。Cowork、Code、MCP、扩展功能开关与“已真正运行相应工作流”是两回事。原例启用功能开关，但未证明登录后的所有任务路径。

## 6. 只针对 Claude 的外部链接适配

适配入口在主进程启动文件加载原程序前调用 `install`，保存原来的 `shell.openExternal`。HTTP/HTTPS 请求使用 `spawn(executable, args, {shell:false})` 启动专用 Edge，URL 原样作为单独参数传递。明确的 `microsoft-edge:https://...` 包装也转入专用浏览器。非网页协议保持原处理逻辑，因此不会把 `claude://` 回调改成网页。

浏览器文件缺失、资料目录缺失或进程启动错误时返回错误，不调用日常浏览器兜底。进程成功创建不等于页面加载成功，所以历史验收还核对进程来源与实际窗口。适配器状态文件只记录计数/时间/进程号，不存 URL；这不保证原应用、浏览器或 MCP 自身完全不记录敏感内容。

源码提供 `--claude-private-edge-check` 固定诊断开关，只在明确带该参数启动 Claude 时通过适配接口打开公共 IP 检测页，不访问账号或读取令牌。普通桌面启动不触发诊断。

打补丁时：备份 EXE、ASAR、防护清单；校验输入哈希；只增加原创模块与启动调用；更新 ASAR 文件摘要和 EXE 内对应的 ASAR 头摘要；保持 Electron fuse 不变；更新自身防护清单中 EXE 的哈希。不能将“摘要一致”说成“厂商签名有效”。任何写入失败应恢复原始字节，回滚也必须校验当前目标是否又被别的修改改变。

公开的补丁脚本是脱敏历史参考，不支持猜版本、盲目查找替换、自动改签名或自动关闭校验。需要独立适配和审核后再用。

## 7. 按顺序部署与验收

1. 盘点现有安装、运行任务、系统 HTTP/HTTPS 默认关联、回调协议和现有策略；保存本地备份，不上传。
2. 准备独立浏览器目录和空 Profile；核对签名、真实文件副本及沙箱 ACL。
3. 准备已授权的代理，先独立测试；不要把凭据写进公开模板或日志。
4. 审核并按完整路径施加规则；对测试探针先做阳性对照，记录每项增量以便精确回退。
5. 验证实际浏览器的固定代理、直连失败、代理中断失败、UDP/DNS 对照和 WebRTC 观察。
6. 接入并验证 MCP；先关闭手动专用窗口，避免 Profile 锁冲突。
7. 备份并适配 Claude 外部链接入口，使用无账号的固定测试页验证；再检查其他应用和默认关联未变。
8. 用户自己完成登录/验证码/授权，再验收真实 Claude 调用 MCP、Code/Cowork 子进程等工作流。
9. 演练回滚、冷启动和更新后的重新登记。登录开机任务只负责代理，不自动启动 Claude。

## 8. 从本机案例到可公开项目

保留“原始私有配置”“脱敏历史结果”“通用只读检查”“参考实施脚本”四个层次。不要把脱敏后不能直接运行的脚本包装成一键工具，也不要把过去某台电脑的 PASS 当作下载者机器的 PASS。所有检查必须输出 PASS / FAIL / UNVERIFIED，而不是缺数据就通过。

当前阶段完成了源码整理、双语说明、静态审计器、单元测试和公开包检查。尚缺全新 Windows 虚拟机部署测试、登录后真实工作流、安全边界进一步审计、维护者署名与最终发布授权，见 [发布门禁](RELEASE.md)。
