## Short Announcement

For users in China and other cross-region setups concerned about account restrictions, Claude Private Browser Kit focuses on what can be inspected locally: mixed browser profiles, unintended direct traffic, desktop/MCP routing differences, and DNS / WebRTC observations.

Give the repository link to an AI agent with local file and terminal access. It handles inspection, version adaptation, backups and verification; you control authorization and login.

**Tested on Windows, with a specific scope:** one local case verified dedicated browser data, external-link routing, configured egress, IPv4 direct-traffic blocking and proxy-failure protection. This is not evidence of reduced ban rates, detection avoidance, or a completed authenticated workflow.

Repository: https://github.com/jiusi1-cpu/claude-private-browser-kit

## Positioning

Account restrictions are the audience concern. Environment auditing and separation are the deliverable. The relationship between these local conditions and Claude enforcement is unknown; do not imply a causal result.

The toolkit preserves the Windows default browser and provides readable source, bilingual agent runbooks, controlled verification checklists and rollback references. It is a research preview, not a universal installer or a complete sandbox.

[The 2026-09-30 Windows case](LOCAL-CASE.md) records observations and limitations. Fresh-machine deployment, all child-process routes, long-term egress stability and authenticated model-driven MCP remain unverified. A surviving account is not a controlled experiment.

This project does not supply accounts or proxy services, reverse-engineer or bypass platform detection, or establish regional eligibility. Use only accounts, networks and services you are authorized to access.
